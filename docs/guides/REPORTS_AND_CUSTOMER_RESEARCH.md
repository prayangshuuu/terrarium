# TERRARIUM — Reports, Evidence & Simulated Customer Research

> **Role**: Platform Architecture & Product Interface Lead (A1 & A5 Lead).  
> **Status**: Comprehensive guide covering report schema, provenance verification, preserved disagreements, and simulated customer feedback standards.

---

## 1. Overview & Architectural Principles

Reports in TERRARIUM (accessible via OpenTUI Workspace 8 or `terrarium report` CLI commands) are structured, durable deliverables synthesizing multi-agent findings, code inspection results, test outputs, and simulated user feedback.

In strict alignment with `PLAN.md` Section 8 & 15 and `PLAN_CONTEXT.md` Section 5:
- **Reports preserve meaningful disagreement**: Consensus is never manufactured when specialists hold legitimate differing perspectives.
- **Evidence provenance is mandatory**: Recommendations cite evidence from repository files, test runs, or explicitly identified sources.
- **Simulated feedback is never misrepresented**: Synthetic persona reactions are clearly flagged as exploratory hypotheses and never conflated with real human customer data.

## 2. Canonical Report Schema

Every report generated by `ReportService` conforms to the `Report` contract in `@terrarium/contracts`:

```text
┌────────────────────────────────────────────────────────┐
│                      Report Header                     │
│  ID, Title, Report Type, Task ID, Generated Timestamp  │
├────────────────────────────────────────────────────────┤
│             Executive Summary & Objective              │
│  Concise outcome narrative and intended goals          │
├────────────────────────────────────────────────────────┤
│                 Evaluation Methodology                 │
│  Tools executed, files inspected, test boundaries      │
├────────────────────────────────────────────────────────┤
│                   Structured Findings                  │
│  Severity (Critical/High/Med/Low), Category, Location  │
├────────────────────────────────────────────────────────┤
│                Evidence Items & Sources                │
│  Verified facts, file checksums, test execution logs   │
├────────────────────────────────────────────────────────┤
│           Preserved Specialist Disagreements           │
│  Perspectives, conflicting stances, trade-offs         │
├────────────────────────────────────────────────────────┤
│              Prioritized Recommendations               │
│  Priority (P0 - P3), owner role, next action steps     │
├────────────────────────────────────────────────────────┤
│              Synthetic Research Disclaimer             │
│  Mandatory notice if synthetic personas participated   │
└────────────────────────────────────────────────────────┘
```

## 3. Epistemic Classification

To prevent ambiguity between verified empirical facts and agent-generated conjecture, evidence items are classified into four strict types:

| Claim Type | Definition | Verification Standard |
|:---|:---|:---|
| `verified_fact` | Ground truth derived directly from tool execution. | Sourced from file checksums, compiler errors, or test runner outputs. |
| `generated_analysis` | Deduction or synthesis produced by an agent profile. | Clearly attributable to a specific agent's analytical reasoning. |
| `assumption` | Operational premise adopted due to missing project context. | Explicitly highlighted as an unconfirmed hypothesis. |
| `simulated_feedback` | Subjective reaction generated by a simulated persona archetype. | Flagged with `isSimulated: true` and simulation disclaimer. |

## 4. Simulated Customer Research Standards

When tasks evaluate product usability, pricing hypotheses, or feature positioning, TERRARIUM can recruit synthetic persona archetypes (e.g. *Enterprise DevOps Lead*, *Startup Founder*, *Security Compliance Auditor*).

### Mandatory Disclaimer
Every report containing simulated feedback includes the canonical disclaimer:

> **SIMULATION NOTICE**: This report contains synthetic responses generated by simulated customer personas for concept exploration and hypothesis generation. These responses DO NOT represent empirical customer research, real human user feedback, statistically valid survey results, or measured market conversion rates. All persona reactions and pricing hypotheses must be validated through real-world customer research.

### Prohibited Claims
Under no circumstances may agent reports or documentation claim:
1. That synthetic personas represent statistically valid sample sizes.
2. That persona feedback replaces real user discovery interviews.
3. That willingness-to-pay numbers from simulated feedback reflect real market price elasticity.

## 5. CLI Report Commands

```bash
# 1. Generate a structured report from completed task deliverables
terrarium report generate --task <task-id> --type final_recommendations

# 2. Run synthetic customer simulation with disclaimer
terrarium report simulate --task <task-id> --personas devops_lead,security_officer

# 3. List all generated reports in local SQLite storage
terrarium report list

# 4. View formatted report with colorized findings in terminal
terrarium report view <report-id>

# 5. Export report as standard GitHub-flavored Markdown
terrarium report export <report-id> --output ./docs/AUDIT_REPORT.md
```
